# Effects of Ambient Dimension and Active-Subspace Alignment on Bayesian Optimisation and CMA-ES

This repository contains the code and report for our study of Bayesian Optimisation (BO) and CMA-ES on objectives with low-dimensional linear structure,

$$
f_A(x)=g(A^\top x),
$$

where the effective dimension is fixed at $k=2$, while the ambient dimension and orientation of the active subspace are varied.

The experiments compare five optimisation methods:

- Random search
- Isotropic BO
- ARD-BO
- Oracle BO
- CMA-ES

The submitted report is located in `report/`.

## Environment and Dependencies

The experiments were run using **Python 3.12.16** in an Anaconda environment. Anaconda is not required to reproduce the experiments.

The required Python packages and versions are listed in `requirements.txt`. They can be installed using:

```bash
pip install -r requirements.txt
```

The main dependencies are NumPy, SciPy, pandas, scikit-learn, CMA-ES (`cma`), joblib, and Matplotlib.

## Data

This project does not use an external dataset. All problem instances, initial designs, active-subspace embeddings, and objective evaluations are generated by `code/run_long_parallel.py` from the specified configuration and random seeds. Generated experimental outputs are stored in `data_long3/` and are not tracked by Git.

## Reproducing the Experiments

### 1. Generate Experimental Results

The experiment runner is executed using:

```bash
python code/run_long_parallel.py
```

By default, the script is configured to run a small **smoke test**, allowing the implementation and environment to be checked without running the full computationally expensive experiment.

The configuration used to generate the results reported in the paper is also provided in `run_long_parallel.py`. To reproduce the reported experiments, replace the active smoke-test configuration with the provided full experimental configuration before running the script.

The reported experiment uses:

- objectives: norm and Branin;
- ambient dimensions: $d\in\{2,5,10,20\}$;
- effective dimension: $k=2$;
- 20 initial-design sets per ambient dimension;
- 20 random rotated embeddings and one axis-aligned embedding per ambient dimension;
- 5 initial evaluation points per initial design;
- evaluation budget: 150 objective evaluations;
- master seed: 42.

All stochastic components are generated deterministically from the master seed, including the initial designs, active-subspace embeddings, and solver-specific randomness.

Independent problem-solver runs are parallelised across CPU workers. The reported experiment used 8 workers and took approximately 10 hours on the machine used for this study; runtime will vary with hardware and the number of workers. The smoke-test configuration is therefore recommended for first verifying the environment and implementation.

### Generated Experimental Data

Running `run_long_parallel.py` creates the directory:

```text
data_long3/
├── config.json
├── versions.json
├── problems/
│   └── ...
└── runs/
    └── ...
```

`config.json` records the resolved experiment configuration used for the run, while `versions.json` records the relevant software versions.

The `problems/` directory stores the generated problem instances, including the active-subspace matrices and initial designs. The `runs/` directory stores the outputs and diagnostics for individual problem-solver runs.

`data_long3/` consists entirely of generated experimental outputs and is excluded from Git version control. It can be regenerated by running `run_long_parallel.py`.

## Reproducing the Main Analysis

After `data_long3/` has been generated, run the following notebook from start to finish:

```text
code/bo_cma_data_analysis.ipynb
```

This notebook processes the raw experimental outputs in `data_long3/` and generates the main experimental plots, with an option to save the figures. Processing the complete experimental dataset took approximately **10 minutes** on the machine used for this study; runtime may vary across hardware.

To speed up subsequent analysis, the notebook also generates a processed cache:

```text
data_long3/
└── cache/
    ├── processed_records_manifest.json
    └── processed_records.pkl
```

The cache is derived entirely from the raw experimental outputs and is used by the subsequent diagnostic analyses. It can be deleted and regenerated by rerunning `bo_cma_data_analysis.ipynb`.

The generated cache is excluded from Git version control.

## Reproducing the Diagnostic Analyses

The diagnostic notebooks investigate the unexpected observations discussed in the report. Both provides the option to save plot files.

They should be run **after `bo_cma_data_analysis.ipynb`**, since they use the processed cache generated by the main analysis.

### ARD-BO vs Oracle BO

Run:

```text
code/diagnostics_ard_oracle.ipynb
```

This notebook investigates why ARD-BO can outperform Oracle BO on the axis-aligned norm objective. In particular, it examines improvement from initialization and the fitted GP length scales.

### Oracle BO and Ambient Dimension

Run:

```text
code/diagnostics_oracle_dim.ipynb
```

This notebook investigates the deterioration of Oracle BO on the Branin objective as ambient dimension increases. It examines the locations of Oracle BO evaluations in the effective space and their increasing concentration near the origin.

For a quick check of the implementation and environment, run `run_long_parallel.py` using its default smoke-test configuration.

For a complete reproduction of the submitted experiments, activate the **full experimental configuration provided in `run_long_parallel.py`**, run the experiment to generate `data_long3/`, and then run the analysis and diagnostic notebooks in the order shown above.
